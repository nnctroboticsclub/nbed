# v0.10.0

日付: 2026-10-28

F303K8・F446RE・F767ZI に PWM DMA と UART DMA を追加するプレリリースです。
PWM と DMA を使う WS2812B の点灯例を追加しました。

## 追加した機能

- `Pwm::SendDataDma()` を実装し、CCR の比較値配列を非同期に出力できます。
  タイマ更新イベントと CCR プリロードを使い、デューティ0の要素も転送します。
- `GetPeriodTicks()`、`GetDmaStatus()`、`StopDma()` を追加しました。
  最後の2要素を0にすることで、完了時には最後のパルスまで出力済みとなり、Lowを維持します。
- PWM DMA は通常のCH出力でタイマを占有します。N出力・相補ペア・循環転送は対象外です。
  既存の通常PWMと相補出力のAPIは引き続き使えます。
- `Uart::SendDma()` / `ReceiveDma()` を追加しました。送受信は独立した非同期の単発転送です。
  `GetTxDmaStatus()` / `GetRxDmaStatus()` で完了を確認し、`StopDma()` で中断・解放できます。
  受信DMAと既存の1バイト受信割り込みは排他的です。
- DMAチャネル・ストリームの予約、IRQ、初期化失敗・中断・破棄・エラー時の処理を3系列で共通化しました。
  競合する要求は開始を拒否し、先に使用している転送を維持します。
- F7でD-cacheの設定を保持し、TX前のclean、RX前後のキャッシュ整合性処理に対応しました。
  対応SRAMの範囲と、D-cache有効時のRXバッファの32 byte境界・長さを検証します。
- `f3-ws2812b` / `f4-ws2812b` / `f7-ws2812b` を追加しました。
  PA8 / TIM1 CH1、800 kHz、GRB順、300 µs以上のリセットLowで16個のLEDを制御します。
  PWMの実際の周期から比較値を計算し、固定のCPUクロックに依存しません。
- `f3-uart-dma` / `f4-uart-dma` / `f7-uart-dma` を追加しました。
  USART2 / PA3 RX・PA2 TX、115200 bpsで32バイトの受信・返信を行います。
- [DMA ガイド](https://github.com/nnctroboticsclub/nbed/blob/v0.10.0/docs/dma.md)に
  配線・バッファの寿命・状態・割当て競合・F7キャッシュ・移行上の注意をまとめました。

## 利用例

```ini
lib_deps =
    https://github.com/nnctroboticsclub/nbed.git#v0.10.0
```

```cpp
Pwm output(kTim1, kCh1, kPA8, 800'000);
if (!output.Initialize()) { System::ErrorHandler(); }
static std::array<uint32_t, 5> waveform{20, 40, 20, 0, 0};
if (!output.SendDataDma(waveform)) { System::ErrorHandler(); }
// GetDmaStatus()で完了を確認してからバッファを再利用する。
```

WS2812Bには [`examples/ws2812b/main.cc`](https://github.com/nnctroboticsclub/nbed/blob/v0.10.0/examples/ws2812b/main.cc)
のエンコード処理を使用してください。送信バッファは完了・中断まで生存し、内容を維持する必要があります。
アプリ側でタイムアウトを設け、IRQを有効にした状態で使用してください。

## 互換性と制約

- 予約APIだった `SendDataDma()` の戻り値を `void` から `bool` へ変更しました。
  結果を無視していた呼出しはコンパイルできますが、開始結果を確認してください。
  独自の `interface::Pwm` / `interface::Uart` 実装は追加メソッドへの対応が必要です。
- 旧F4の内部用 `Dma1`〜`Dma7` / `DmaManager` を、要求に応じたDMAの所有権管理へ置き換えました。
  `System::Initialize()` は未使用DMAのIRQをまとめて有効化しなくなりました。
- DMAの完了後も資源を保持します。ほかの用途へ譲る場合は `StopDma()` を呼んでください。
- UART受信DMAは指定長が揃うまで待つ方式です。IDLE検出・可変長・リング受信は提供しません。
- ADC・SPIのDMA、PWM相補出力のDMA、循環転送、自動的な代替ストリーム選択は対象外です。

## 検証

- 既存の22環境と新しい6環境、計28環境のビルドが成功しました。
- 公開対象のソースから回帰テスト50件を実行し、41件が成功しました。
  F7のPWM出力設定1件はコンパイル成功ですが、Windowsのアプリ制御（4551）により実行をスキップしました。
  任意のPlatformIO統合テスト8件もスキップしています。
  DMAのF3/F4/F7テストはコンパイル・実行とも成功しています。
- DMAの要求割当て・二重予約・未所有IRQ・優先度・開始失敗・中断・破棄、
  PWMの入力境界・末尾ゼロ・設定変更拒否、UARTの状態・モード排他・エラー・所有者の照合、
  GRBエンコード・パルス幅計算、SRAM境界とF7キャッシュ操作を確認しました。
- 公開対象だけから作った配布パッケージの内容を照合し、別プロジェクトから
  F3/F4/F7でPWM DMA・UART DMAを使ってビルドしました。
  グローバル名・グローバル待機関数・既定コンソールを無効にした構成と、DMAハンドラーのリンクも確認しました。
- 実機への書込み、WS2812Bの点灯、実際の波形、UART通信、高負荷時のDMA遅延は未検証です。
