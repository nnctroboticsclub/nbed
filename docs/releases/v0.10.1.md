# v0.10.1

日付: 2026-10-28

F446RE・F767ZIで、CANのRX/TXを固定のペアでしか指定できなかった不具合を修正するパッチリリースです。
PA11 RX・PB9 TXなど、同じCANの有効なRX候補とTX候補を個別に選択できます。
従来と同じGitHubのプレリリースとして公開します。

## 修正内容

- CAN1/CAN2のピン検証を、RX候補とTX候補をそれぞれ判定する方式に修正しました。
  RX/TXの逆転、別のCANのピン、未対応ピン、不正な周辺機能番号は引き続き拒否します。
- 異なるGPIOポートのRX/TXを初期化できるようにしました。
  停止・破棄・HAL初期化失敗・フィルタ設定失敗時も、各ポートの該当ピンを解放します。
- F3/F4/F7のCAN回帰テストと、RX/TXを個別に選択できることを示すピン表を追加しました。

## 利用例

```ini
lib_deps =
    https://github.com/nnctroboticsclub/nbed.git#v0.10.1
```

F446RE・F767ZIでは次の指定が可能です。

```cpp
Can can(kCan1, kPA11, kPB9, 1'000'000);
if (!can.Initialize() || !can.Start()) {
  System::ErrorHandler();
}
```

RX/TXは同じCANの行から、それぞれ選択します。

| MCU | CAN | RX | TX |
| --- | --- | --- | --- |
| F446RE | CAN1 | PA11 / PB8 | PA12 / PB9 |
| F767ZI | CAN1 | PA11 / PB8 / PD0 | PA12 / PB9 / PD1 |
| F446RE・F767ZI | CAN2 | PB5 / PB12 | PB6 / PB13 |

公開APIの変更はありません。既存のピン指定とF303K8のPA11 RX・PA12 TXも引き続き使用できます。
通常通信には外部CANトランシーバと終端抵抗が必要です。

## 検証

- 既存の全28環境のビルドが成功しました。
- 公開対象のソースからUbuntu上で回帰テスト53件を実行し、45件が成功しました。
  任意のPlatformIO統合テスト8件はスキップしています。
  Windowsのアプリ制御で実行できないテストも、Ubuntuではコンパイル・実行とも成功しました。
- 修正前のv0.10.0ではF4/F7の新しいCANテストが初期化失敗を検出し、修正後はF3/F4/F7で成功しました。
- CAN1の全RX/TX候補の組み合わせ、CAN2の混在指定、GPIOのポート・ピン・AF、
  不正な指定、二重所有、割り込み優先度、停止・再開、HAL初期化・フィルタ設定失敗後の解放、
  CAN2動作中のCAN1クロック維持を確認しました。
- 配布パッケージ126ファイルが公開対象ソースと一致することを確認しました。
  そのパッケージを使った別プロジェクトからF3/F4/F7をビルドし、PA11 RX・PB9 TX、
  CAN2のPB5 RX・PB13 TX、F7のPD0 RX・PA12 TXを含むコードのリンクを確認しました。
  グローバル名・グローバル待機関数・既定コンソールを無効にした構成も確認しています。
- 実機への書込み、外部トランシーバを使った通信、信号波形は未検証です。

ピンの代替機能はSTの[F446データシート](https://www.st.com/resource/en/datasheet/stm32f446re.pdf)と
[F767データシート](https://www.st.com/resource/en/datasheet/stm32f767zg.pdf)に記載されています。
