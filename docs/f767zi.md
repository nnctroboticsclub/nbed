# STM32F767ZI / NUCLEO-F767ZI

STM32F767ZIT6（LQFP144）用の実装です。GPIO、ADC1/ADC3、PWM、I²C、SPI、UART、
Classic CAN、エンコーダ、時間待ち・計時を使用できます。
名前空間は `nkrc::nbed::stm32::f7`、通常の入口は `#include "nbed.h"` です。
ほかの F7 型番は対象に含みません。

## 最初のビルド

```sh
pio run -e f7-blink
pio run -e f7-blink -t upload
pio device monitor -e f7-blink
```

基板上の緑 LED（LD1）は **PB0**、青 LED は PB7、赤 LED は PB14 です。
Arduino D13 は PA5 で、既定の LD1 配線とは異なります。
既定コンソールは **USART3、RX=PD9、TX=PD8、921600 bps** です。
ST-LINK の仮想 COM ポートは SB5/SB6 の設定にも依存します。
Arduino D0/D1 は USART6（PG9/PG14）で、ST-LINK の仮想 COM とは別です。

```cpp
#include "nbed.h"

int main() {
  System::Initialize();
  DigitalOut led(kPB0);
  if (!led.Initialize()) {
    System::ErrorHandler();
  }
  while (true) {
    led = !led.Read();
    SleepFor(500ms);
  }
}
```

## 別プロジェクトで使う

```ini
[env:nucleo_f767zi]
platform = ststm32@20.0.0
board = nucleo_f767zi
framework = stm32cube
platform_packages =
  toolchain-gccarmnoneeabi@1.140201.0
  framework-stm32cubef7@1.17.2
board_build.stm32cube.custom_config_header = yes
board_upload.maximum_ram_size = 393216
lib_deps = https://github.com/nnctroboticsclub/nbed.git#v0.10.1
```

C++23、LTO、`-O3`、F7 の実装とリンカスクリプトはライブラリが設定します。
`maximum_ram_size` は既定配置で使用する SRAM1/2 の 384 KiB をビルド時の表示にも反映します。
グローバルの短い名前を出さない `NBED_NO_GLOBAL_NAMES` と、グローバルの待機関数を出さない
`NBED_NO_GLOBAL_FUNCTIONS` も使用できます。

## クロック、キャッシュ、メモリ

既定では ST-LINK MCO 由来の 8 MHz HSE bypass を使います。
PLL M=8 / N=432 / P=2 / Q=9、SYSCLK/HCLK=216 MHz、PCLK1=54 MHz、PCLK2=108 MHz です。
Voltage Scale 1、OverDrive、Flash 7 wait states を設定します。
クロック上限、APB 分周値、PLL、`HSE_VALUE`、Flash 待機数を検証してから初期化します。
タイマの TIMPRE は 0 とし、APB 分周が1なら PCLK、それ以外なら 2×PCLK を使用します。

外部クロックを使わない場合の設定例:

```cpp
Clock::Configuration clock{};
clock.oscillator_source = Clock::OscillatorSource::kHsi;
clock.pll_m = 16;  // HSI 16 MHz / 16 -> PLL 入力 1 MHz
System::Initialize(clock);
```

HSE の別周波数を使う場合は `hse_frequency_hz` とビルドフラグの `HSE_VALUE` を一致させます。
電源条件は NUCLEO の 3.3 V を前提とします。周辺機能はクロック設定後に初期化し、
実行中にクロックを変更したら周辺機能も作り直してください。

`System::Initialize()` は命令キャッシュを有効にします。データキャッシュは自動では
有効化しません。PWM/UARTのDMAは現在のD-cache設定に応じてバッファの整合性を管理します。
受信バッファの32 byte境界などは [DMA ガイド](dma.md)を参照してください。
計時は Cortex-M7 の DWT をアンロックして開始し、SysTick と組み合わせます。

Flash は 2 MiB、通常の `.data` / `.bss` / heap / stack は SRAM1/2 の
`0x20020000`〜`0x2007ffff`（384 KiB）に配置します。
物理メモリの残りの DTCM 128 KiB と ITCM 16 KiB は既定配置では使用しません。
専用セクションの起動時初期化や外部 SDRAM は、この版では提供しません。

## 対応ピン

GPIO は PA0〜PG15、PH0/PH1 に対応します。`kNC` は初期化に使えません。
基板の Ethernet PHY、USB、LED、クロック、デバッグに接続されているピンも含むため、
周辺回路・ジャンパ・はんだブリッジとの競合を確認してください。
ピンの所属する機能を個別に検証しますが、異なる種類のドライバ間のピン共有は検出しません。

### Arduino / Zio の短い名前

| 名前 | ピン | 名前 | ピン |
| --- | --- | --- | --- |
| D0 | PG9 | D1 | PG14 |
| D2 | PF15 | D3 | PE13 |
| D4 | PF14 | D5 | PE11 |
| D6 | PE9 | D7 | PF13 |
| D8 | PF12 | D9 | PD15 |
| D10 | PD14 | D11 | PA7 |
| D12 | PA6 | D13 | PA5 |
| D14 | PB9 | D15 | PB8 |
| A0 | PA3 | A1 | PC0 |
| A2 | PC3 | A3 | PF3 |
| A4 | PF5 | A5 | PF10 |

D11 の定義は既定の PA7 配線を想定しています。SB121 OFF / SB122 ON で PB5 側に
切り替えた基板では `kPB5` を明示してください。PA7 は Ethernet PHY とも接続されるため、
SPI 出力として使う場合は JP6 などによる接続を確認します。
A4/A5 も基板のブリッジ設定により I²C の PB9/PB8 側へ変更できます。
短い名前は基板設定を自動検出しません。

### ADC

12 bit の単発変換です。同じ ADC の複数ピンを順番に読み取り、チャンネル設定をキャッシュします。
ADC1 と ADC3 の状態は独立しています。割り込みとメイン処理からの同時呼び出しは未対応です。
ADC クロックは PCLK2/4（既定 27 MHz）です。

| ADC | ピン / チャンネル |
| --- | --- |
| ADC1 | PA0〜PA7=CH0〜7、PB0/PB1=CH8/9、PC0〜PC5=CH10〜15 |
| ADC3 | PF3=CH9、PF5=CH15、PF10=CH8 |

ほかの ADC3 入力と ADC2 はこの API では選択しません。

### PWM / エンコーダ

| タイマ | CH1 | CH2 | CH3 | CH4 |
| --- | --- | --- | --- | --- |
| TIM1 | PA8 / PE9 | PA9 / PE11 | PA10 / PE13 | PA11 / PE14 |
| TIM2 | PA0 / PA5 / PA15 | PA1 / PB3 | PA2 / PB10 | PA3 / PB11 |
| TIM3 | PA6 / PB4 / PC6 | PA7 / PB5 / PC7 | PB0 / PC8 | PB1 / PC9 |

TIM2 は 32 bit、TIM1/TIM3 は 16 bit です。エンコーダは表の CH1 を A相、CH2 を B相として使います。
同じタイマの PWM チャンネルは周波数を共有します。PWM とエンコーダの同時使用、同じ
チャンネルの二重使用は拒否します。TIM4 以降は未対応です。
TIM1 の相補出力・極性・デッドタイム・アイドル状態は、v0.8.0 から対応しています。
使い方と CH1N/CH2N/CH3N のピンは [PWM 出力設定ガイド](pwm.md)を参照してください。
`SendDataDma()` の波形転送とWS2812Bの例は [DMA ガイド](dma.md)を参照してください。

### I²C

| 周辺機能 | SCL | SDA |
| --- | --- | --- |
| I2C1 | PB6 / PB8 | PB7 / PB9 |
| I2C2 | PB10 / PF1 | PB11 / PF0 |
| I2C3 | PA8 | PC9 |

各行の選択肢を組み合わせて使えます。7 bit アドレス、400 kHz 以下で、レジスタに
表現できる速度に対応します。カーネルクロックは HSI 16 MHz 固定、アナログフィルタ有効、
デジタルフィルタ0です。Fast mode は立上り100 ns以下・立下り300 ns以下を前提とし、
設定する周期は指定速度を超えないようにします。実速度には HSI と信号波形の誤差が加わります。
外付けプルアップ抵抗を使用してください。PB7 は青 LED と共用です。
I2C4 は未対応です。

### SPI

| 周辺機能 | SCK | MISO | MOSI |
| --- | --- | --- | --- |
| SPI1 | PA5 / PB3 / PG11 | PA6 / PB4 / PG9 | PA7 / PB5 / PD7 |
| SPI2 | PA9 / PA12 / PB10 / PB13 / PD3 | PB14 / PC2 | PB15 / PC1 / PC3 |
| SPI3 | PB3 / PC10 | PB4 / PC11 | PB2 / PB5 / PC12 / PD6 |

8 bit マスター、モード0〜3、MSB/LSB順、送信・受信・同時送受信に対応します。
速度指定の上限は SPI1 が54 MHz、SPI2/3 が27 MHz（3.3 V）です。
既定クロックで 1 MHz を指定すると843750 Hzになります。
SPI4/5/6 は未対応です。CS 操作などは [SPI ガイド](spi.md)を参照してください。

### UART

| 周辺機能 | RX | TX |
| --- | --- | --- |
| USART2 | PA3 / PD6 | PA2 / PD5 |
| USART3 | PB11 / PC11 / PD9 | PB10 / PC10 / PD8 |
| UART4 | PA1 / PC11 / PD0 | PA0 / PC10 / PD1 |
| USART6 | PC7 / PG9 | PC6 / PG14 |

各行の RX/TX を組み合わせます。USART3 の PD9/PD8 が既定コンソールで使用中のため、
同じ USART3 をアプリで使う場合は `NBED_NO_DEFAULT_SERIAL` を定義します。
通常の送受信はブロッキングで、1 byte の受信割り込みにも対応します。
USART1、UART5/7/8 は未対応です。対応UARTのDMA送受信は [DMA ガイド](dma.md)を参照してください。

### CAN

| 周辺機能 | RX | TX |
| --- | --- | --- |
| CAN1 | PA11 / PB8 / PD0から選択 | PA12 / PB9 / PD1から選択 |
| CAN2 | PB5 / PB12から選択 | PB6 / PB13から選択 |

同じCANのRX候補とTX候補は個別に選べます。PA11 RX・PB9 TXや
PD0 RX・PA12 TXなど、異なるGPIOポートの組み合わせにも対応します。

Classic CAN、最大1 Mbps、FIFO0 受信、標準/拡張 ID フィルタに対応します。
通常通信には外部 CAN トランシーバと終端抵抗が必要です。CAN3 と CAN FD は未対応です。
CAN1/2 はフィルタバンク0〜13 / 14〜27を使い、CAN2 の動作中は CAN1 のクロックを維持します。

## 検証用サンプル

- `f7-blink`: PB0 の LED と既定コンソール。
- `f7-all-test`: ADC1/ADC3、GPIO、PWM、タイマ所有権の解放とエンコーダ初期化、
  I²C 初期化、USART6 受信割り込み、CAN1 内部ループバック、計時をリンクする確認用。
- `f7-spi-test`: PB5（Zio D22 / Morpho）とD12（PA6）を接続する SPI1 ループバック。
  既定の D11（PA7）を使用せず、Ethernet PHY との競合を避けます。

ビルドとホスト上の代替 HAL によるテストは実施しています。実機への書込み、外部機器との
通信、PWM/SPI/I²C/CAN の波形、受信割り込みの負荷試験は未実施です。
F7 対応は検証途中の実装として使用してください。

## 外部割り込み（EXTI）

`InterruptIn` で立上り・立下り・両エッジを検出できます。GPIO の末尾番号が同じピンは
同時に使えません。共有 IRQ の優先度を揃え、基板上の周辺機器と共用するピンを避けてください。
API、制約、各ボードの試験ピンは [EXTI ガイド](exti.md)にあります。
`f7-exti-test` は PA0 の入力レベル・イベント累計・コールバック回数を表示します。
